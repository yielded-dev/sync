## Atom bindings

Define bindings once. The registry owns their connections; dispose it before
switching actors. `actorId` selects local ownership and must match your session,
but it does not authenticate requests. The server still verifies the connection.

## Persistence

To retain pending edits across reloads, replace `"volatile"` with an IndexedDB
Layer in `counter-atoms.ts`:

```ts
import { IndexedDb } from "@yielded/sync-local-indexeddb";

const persistence = IndexedDb.layer({ namespace: "counter" });
```

`BrowserSource.bind` supplies the Layer's actor. Keep the namespace stable and
close the session before changing actors or storage.

| Stored data             | What it is for                                         |
| ----------------------- | ------------------------------------------------------ |
| Pending-command journal | Retrying unresolved edits with their original identity |
| Snapshot cache          | Showing the last known state while reconnecting        |

Never delete the journal to repair a cache. Browser quota or permission failures
can refuse new edits; persistent mode does not silently switch to volatile mode.

## Compose actions

Use `counter.fn` to combine actions with other atoms. Here the draft clears only
after the server accepts the change:

```ts
import { Atom } from "effect/reactivity";

import { counter } from "./counter-atoms";

export const draft = Atom.make(0);
export const save = counter.fn(function* () {
  const value = yield* Atom.get(draft);
  yield* counter.action.set({ value });
  yield* Atom.set(draft, 0);
});
```

Use `useAtom(save)` in React, just like `counter.action.set`. The configured
optimistic reducer updates the view while the action is pending. Its result and
the confirmed replica can arrive independently.

## Open a source

For an app without React, compose the transport and actor services directly.
Keep the client and its lease inside an Effect scope:

```ts
import { Client } from "@yielded/sync/client";
import { Effect, Layer } from "effect";
import * as Socket from "effect/socket/Socket";

import { CounterClient } from "./counter-client";
import { Counter, CounterId } from "./counter";

const id = CounterId.make("demo");
const transport = Client.layerWebSocketTransport(Counter, {
  origin: "https://app.example.com",
  id,
}).pipe(Layer.provide(Socket.layerWebSocketConstructorGlobal));

export const setCounter = Effect.gen(function* () {
  const session = yield* Client.make(CounterClient, { persistence: { mode: "volatile" } });
  const lease = yield* session.open(Counter.address(id));

  yield* lease.ready;
  return yield* lease.execute(Counter.actions.set, { value: 7 });
}).pipe(
  Effect.provide(transport),
  Effect.provideService(Client.CurrentActor, { actorId: "alice" }),
  Effect.scoped,
);
```

This Effect returns `{ previous, current }` and closes the connection when it
finishes. For a live view, consume `Client.view(lease).changes` inside the same
scope. Persistent headless sessions use `{ mode: "persistent" }` and require a
`ReplicaPersistence` Layer for that actor.

### Transport

The WebSocket transport derives the path from `Counter` and encodes the ID.
Browser bindings default to the page origin; `origin` and `query` override the
connection settings. The app owns credentials. This transport serves one source
address; multi-address apps need a routing transport. See the
[transport API](https://github.com/yielded-dev/sync/blob/main/packages/sync/src/client/Transport.ts)
for custom URLs and RPC composition.

## Retry and recovery

A lost response does not mean the edit failed:

      lane: "library",

      detail: "The edit is not applied again.",
    },
  ]}
/>

| Headless operation               | When to use it                                                 |
| -------------------------------- | -------------------------------------------------------------- |
| `lease.execute(action, payload)` | Submit an edit and wait for its result                         |
| `lease.enqueue(action, payload)` | Return its ID after local admission; deliver in the background |
| `lease.retry(commandId)`         | Recover an uncertain result using the original command         |
| `lease.recover`                  | Restart a parked connection                                    |

`enqueue` needs a known server authority, which can come from a restored cache.
Its returned ID confirms local admission, not server acceptance. Observe
`pending`, `failures`, and `error` on the replica; React bindings expose `retry`
and `recover` atoms for the same recovery operations.

An uncertain `ClientError` carries its `commandId`. Retry that ID rather than
submitting a new edit. If a result expires or the server authority changes,
retain the unresolved command for application reconciliation. Dismissing a
terminal failure with `dismissFailure` does not resolve uncertain work.

See the [client API](https://github.com/yielded-dev/sync/blob/main/packages/sync/src/client/Client.ts)
for connection limits and retry defaults. The
[React board](https://github.com/yielded-dev/sync/tree/main/examples/list-board)
also shows presence, persistent sessions, concurrent actions, and UI recovery.
