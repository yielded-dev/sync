title: Packages and hosts
---

Install only the integrations your app needs. Keep Sync packages on the same
exact version; their manifests define supported Effect and framework peers.

## Cloudflare

Both integrations use the same `DurableObject.make` definition. Choose the
framework that already owns your Worker and pass its provider to `.provide(...)`:

```sh
bun add @yielded/sync-platform-cloudflare@{{SYNC_VERSION}} \
  @yielded/sync-platform-effect-cf@{{SYNC_VERSION}} effect-cf
```

Or, for Alchemy:

```sh
bun add @yielded/sync-platform-cloudflare@{{SYNC_VERSION}} \
  @yielded/sync-platform-alchemy-cf@{{SYNC_VERSION}} @alchemy.run/cloudflare alchemy
```

| Framework | Provider           | Example                                                                                               |
| --------- | ------------------ | ----------------------------------------------------------------------------------------------------- |
| effect-cf | `EffectCfServices` | [Counter Worker](../api/consumer.md#host-on-cloudflare)                                               |
| Alchemy   | `AlchemyServices`  | [Alchemy setup](https://github.com/yielded-dev/sync/blob/main/packages/platform-alchemy-cf/README.md) |

Each adapter supplies SQLite, crypto, transport, and lifecycle hooks. Your app
supplies authentication. Replace SQLite by passing a `SourceStorage` Layer as
`storage` to `DurableObject.make`.

## Other hosts

Use `Server.host` with your own `SourceStorage` and `ServerCrypto` Layers.
Keep one host per storage authority and keep its scope alive for its connections.
`ServerRpc.handlers` connects the host to an Effect RPC transport; provide
`ServerRpc.CurrentConnection` from authenticated server context.

See the [host API](https://github.com/yielded-dev/sync/blob/main/packages/sync/src/server/Host.ts)
for limits and outbox scheduling, and the
[RPC API](https://github.com/yielded-dev/sync/blob/main/packages/sync/src/server/Rpc.ts)
for transport composition.

## Browser clients

```sh
bun add @yielded/sync-platform-browser@{{SYNC_VERSION}} \
  @yielded/sync-local-indexeddb@{{SYNC_VERSION}} @effect/atom-react react
```

`BrowserSource.bind` supplies browser services and Atom bindings. Add an
`IndexedDb` Layer to retain pending edits across reloads, or choose `"volatile"`.
See [client setup](../client.mdx).

For custom persistence, implement `ReplicaPersistence` directly or use
[`Persistence.make`](https://github.com/yielded-dev/sync/blob/main/packages/persistence/README.md)
for shared record handling over your storage drivers.

## Imports

| Entry point                      | Main APIs                                              |
| -------------------------------- | ------------------------------------------------------ |
| `@yielded/sync`                  | `Source`, `Action`, `Plugin`, schemas and errors       |
| `@yielded/sync/server`           | `Server`, `ServerRpc`, `SourceStorage`, `ServerCrypto` |
| `@yielded/sync/client`           | `Client`, `ReplicaPersistence`                         |
| `@yielded/sync/atom`             | `SourceAtom` for custom Atom runtimes                  |
| `@yielded/sync-platform-browser` | `BrowserSource`                                        |
| `@yielded/sync-local-indexeddb`  | `IndexedDb`                                            |
| `@yielded/sync-persistence`      | `Persistence` and storage driver contracts             |

Public modules also support direct imports:

```ts
import * as Source from "@yielded/sync/Source";
import * as Client from "@yielded/sync/client/Client";
```
