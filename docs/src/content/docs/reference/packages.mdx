Core contracts and `Server.host` are portable. Add an optional server adapter for
native transport and lifecycle hooks, and client persistence for restart recovery.

| Entry point                         | Use it for                                                      |
| ----------------------------------- | --------------------------------------------------------------- |
| `@yielded/sync`                     | Shared contracts, with `./client` and `./atom` entry points     |
| `@yielded/sync/server`              | `Server.host`, `ServerRpc`, execution, and server storage ports |
| `@yielded/sync-platform-browser`    | `BrowserSource`: browser services and source Atom bindings      |
| `@yielded/sync-persistence`         | `Persistence`: shared record policy and custom drivers          |
| `@yielded/sync-local-indexeddb`     | `IndexedDb`: browser persistence                                |
| `@yielded/sync-platform-cloudflare` | `Cloudflare` transport and lifecycle; `SqliteStorage`           |
| `@yielded/sync-platform-effect-cf`  | `EffectCf`: native effect-cf Workers and Durable Objects        |
| `@yielded/sync-platform-alchemy-cf` | `AlchemyCf`: native Alchemy Workers and Durable Objects         |

`Server.host` owns ordering, subscriptions, publication, and optional outbox
delivery. Supply `SourceStorage` and `ServerCrypto`; connect it to Effect RPC with
`ServerRpc.handlers`. Applications own authentication, routing, transport,
durable wakeup scheduling, and projection destinations.

The Cloudflare packages adapt this same host to native requests, WebSockets, and
alarms. Pick the framework matching your application; neither requires the other.
They supply native SQLite and crypto by default; pass a custom `SourceStorage`
Layer in `storage` to replace SQLite. Generated handlers share the source's path
and ID schema with the client; the application supplies authentication.
Their `layer(options)` functions expose
the same platform services for custom composition. Server
implementations are not exported from root or client entry points.

For browser clients, `BrowserSource.bind` derives the connection from the client
definition and ID, supplies browser crypto, and creates the Atom runtime. Supply
an actor and either a persistence Layer or `"volatile"`; credentials remain
application-owned. Use `SourceAtom.bind` for custom runtime composition.

IndexedDB remains subject to browser quota and eviction. It uses
`@yielded/sync-persistence` and retains unresolved command journals separately from disposable snapshot
caches. See [client persistence](../client.mdx#persistence).

Keep Sync packages on the same exact version. Package manifests declare supported
Effect and framework peer ranges; the repository catalog pins the development
combination. Read the [upgrade guidance](../RELEASE.md) before changing versions.
